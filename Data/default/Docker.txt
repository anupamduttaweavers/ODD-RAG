*when we develop an application in our local machine then it's require a lots of dependencies and then if someone need to run the application to their own machine then there a problem arises on the installation of the app with their dep. into their own machine here comes the docker container...
Docker Container:
================
So the docker container is simply a single unit packed with both the application with it'd dependencies. So there is no issue of installing all the things separately. 
Properties:-
1.Portable,2.lightweight
Docker Image:
============
So when we complete with our development process then the whole app along with the dependencies becomes a Container now we create a image of the docker container.
Now this image works as the blueprint/snapshot of the container,from which we can create multiple container instances just like the Class and objects and like this we can use those container in the multiple times in multiple different system and that does not effect the global system, it uses the global CPU and power but run only on the container.

Docker commands:
===============
0.docker images -->shows all the images
1.docker pull [image_name] --> pull some images from the docker-hub
2.docker run [image_name] -->create a container from the image
3.docker run -it [image_name] -->create a container in a interactive mode.
**[interactive mode simple give the interactive terminal into the local terminal so that we can interact directly with the created container.]
4.docker ps --> shows all the container running
5.docker ps -a --> shows all the containers both running and stopped
6.docker start [container_name] --> Start a stopped container
7.docker stop [container_name] --> Stop a  running container
8.docker rmi [image_name or id] --> delete a image[**the image should not be used in any of the container both stopped or running]
9.docker rm [container_name or id] --> deleting a container 
10.docker run --name [custom_name] [image_name] --> creates a custom named container.
11.docker run -e [KEY=value] [image_name] for setting up the environment key,and run the container
12.docker run -p[host_port]:[container_port] [image_name] --> used to bind the host port number to the container port number.
13.docker exec -it [container_name or id] /bin/bash--> to go into a running container's interactive terminal and run some commands on them then "exit" to exit from that container.
14.docker network ls --> show all networks 
15.docker network create [Network_name] -->create a custom network

Developing with Docker:
======================
now when we are in the development process then we a  lot of image requirements as dependencies then for the all things we need to pull all of this individually and run them is quite a tedious task for that we create a compose.yaml file where we write all the services we need and all their configuration like port binding and and the environment variables this saves our time a lot.
And the most important thing is that all the services share a common network and the network is created automatically.

There are two commands to run/off those services are
**first we have to go to the project directory where the .yaml file is located then
1.docker compose -f [FILE_NAME].yaml up -d --> run the .yaml file in the detached mode and automatically generate all the containers and networks.
2.docker compose -f [FILE_NAME].yaml down --> this will close all the activated containers permanently in a single command. this is the beauty of this command.

Dockerizing  our App:
====================
create a Dockerfile withing which we have to write all the configuration needed.
FROM source --> this is the base container that need to be installed 
RUN --> run some scripts
COPY --> copy from the source to the destination 
WORKDIR -> this is the working directory
ENV --> environment variables
CMD --> this will be the single command in the docker that will tell after all the setup what is the final thing need to run.
EXPOSE --> to expose some content
